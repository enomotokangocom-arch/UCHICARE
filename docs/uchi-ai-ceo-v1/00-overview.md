# Uchi AI CEO v1 — 概要

## プロダクトコンセプト

「人がケアに集中し、AIが経営を回す。」

訪問看護事業(株式会社Uchi care)の経営における定型的な「収集 → 集計 → 分析 → 予測 → 提案 → 通知」をAIで自動化し、
経営者・管理者は重要な承認・判断だけを行える状態を作る。単なるBIダッシュボードやチャットボットではなく、

```
Detect → Diagnose → Forecast → Decide → Execute → Monitor
```

を1つの経営ループとして実装する「Decision OS」である。

| | BI(既存ダッシュボード) | Uchi AI CEO |
|---|---|---|
| 問い | 何が起こったか | 何が起こったか→なぜ→今後どうなるか→何をすべきか→実行→学習 |
| 提示するもの | 全指標 | 今日見るべきものだけ |

## AI権限レベル(L1〜L5)

| Level | 内容 |
|---|---|
| L1 | データ可視化のみ |
| L2 | 分析・提案まで |
| L3 | 人間承認後にAIが実行 |
| L4 | 低リスク業務をAIが自動実行し、事後報告 |
| L5 | AIが自律実行し、異常・例外のみ人間にエスカレーション |

以下は原則 **L1〜L2に限定**し、AIが最終判断・自動実行しない(`required_approval_level` を `human_only` とする)。

採用最終判断 / 給与決定 / 昇格・降格 / 懲戒 / 退職勧奨 / 重大事故対応 / 虐待対応 / 医療判断 / 大型投資 / M&A最終判断。

Phase 0 では全ての意思決定を **L2(分析・提案まで)** に固定する。承認ボタンはUI上に用意するが、
承認されても「AIが自動実行」する対象(発注・求人票公開・シフト変更など外部への実行アクション)は存在しない
= 実行フェーズは Phase 1 以降のスコープ。

## 対象20意思決定と実装フェーズ

`03-decision-engine.md` の一覧を参照。Phase 0 では以下6項目を実装する。

1. 月末売上予測 (`revenue_forecast`)
2. 月末利益予測 (`profit_forecast`)
3. 看護師別訪問生産性 (`nurse_productivity`)
4. 必要新規利用者数 (`required_new_patients`)
5. 必要営業量 (`required_sales_activity`)
6. 必要採用人数 (`required_hiring`)

残り14項目は `08-risks-and-roadmap.md` の拡張ポイントで設計上の受け皿(データモデル・Decision型)のみ用意し、
実装はPhase 1以降とする。
