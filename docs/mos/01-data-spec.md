## 1. GMOあおぞらネット銀行 明細（`8月GMO.xlsx`）

- 形式: xlsx、1シート。シート名は `statement-<数字>-<数字>-<数字>` 形式。
- 1行目がヘッダー:

| 列 | ヘッダー | 内容 | 正規化 |
|---|---|---|---|
| A | `日付` | `YYYYMMDD`（例 `20260831` の8桁） | `Date`（JST の日付） |
| B | `摘要` | 取引内容（全角・半角カナ混在） | NFKC 正規化 + 空白圧縮 |
| C | `入金金額` | 入金額。空欄＝入金なし | 整数（円） |
| D | `出金金額` | 出金額。空欄＝出金なし | 整数（円） |
| E | `残高` | 取引後残高 | 整数（円） |
| F | `メモ` | 担当者が手入力した用途メモ（任意、例: 家賃・駐車場代・会議費） | 文字列 |

- 並び順: 日付の **降順**。
- 摘要のパターン（確認したもの）:
  - `Visaデビット利用 <加盟店名> 承認番号：<数字> TID：<数字>` … デビットカード即時引落（1件＝1経費）
  - `Visaデビット利用　海外 <加盟店名> …` … 海外利用
  - `Visaデビット取消 …` / `Visaデビット取消（差額分） …` … 取消（入金側に計上される）
  - `振込 <金融機関> <受取人>` … 振込出金 / 振込入金
  - `振込手数料`
  - `AP(<収納代行名>` / `<カナ>(SMCC` … 口座振替
  - `普通預金 利息`
  - `振込 ＧＭＯアオゾラネツト　ＶＩＳＡデビツトキヤツシユバツク` … キャッシュバック（入金）
  - `振込 カ）ウチケア` … **自社名義口座からの入金（口座間振替）**
- 同日・同額・同摘要の行が複数存在しうる（例: 同日の `振込手数料` 100円が複数）。
  → 重複判定キーには **残高** を含める（同日同額でも残高が異なるため区別できる）。

## 3. 居宅売上管理表（`居宅売上管理表.xlsx`）

- 形式: xlsx、**1か月＝1シート** の帳票形式（表形式ではない）。ほかに `入力方法`（記入例）・`売上管理表`（空テンプレート）・`リスト`（サービスコード一覧）シートがある。
- シート名（実ファイル）: `入力方法`, `売上管理表`, `売上管理表 9月`（令和7年9月の値）, `売上管理表 10月` … `売上管理表 5月`,
  `売上管理表 6月 `〜`売上管理表 9月 `（末尾に空白。令和8年度）, `リスト`。**シート名に年が無く、同じ「9月」が2枚ある**ため、シート名は年月の根拠にしない。
- 金額・件数の多くは **数式セル**（例: 総売上 `=SUM(J5,J20,J26,J27)`、小計 `=SUM(D6:D11)`）。計算結果は xlsx に保存されている。
  読み込みに使う exceljs は「計算結果が 0 の数式セル」を値なしとして読み落とすため、xlsx 内の XML から計算結果を直接補っている（`grid.ts`）。
- 列位置（実ファイル）: 旧版 `今月請求`=D(件数)・E(金額)、`月後れ請求`=F・G、`合計`=H・I。
  新版（令和8年6月〜）は `月後れ単価` 列 F が入り、`月後れ請求`=G・H、`合計`=I・J。総売上の数式はいずれも `要介護＋要支援＋委託＋認定調査` の合計列。
- 各月シートのレイアウト:
  - 1行目: `月間売上表`（左ブロック）、`年間売上表`（右ブロック）の見出し
  - 2行目: `令和N年M月`（対象年月）、`総売上` とその金額（左ブロック）、右ブロックにも `総売上`（年度累計）
  - 3行目: 見出し `単価` / `今月請求` / `月後れ請求` / `合計`（左）、`要介護` / `要支援` / `委託` / `合計`（右）
  - 4行目以降（左ブロック）: 区分小計行と明細行
    - 小計行: `要介護`、`要支援` … `今月件数, 今月金額, 月後れ件数, 月後れ金額, 合計件数, 合計金額` の6数値
    - 明細行: `居宅介護支援費`、`初回`、`加算/減算`、`介護予防支援費`、`委託連携`、`認定調査` 等 … 単価＋件数・金額
    - `委託` 行: `合計件数, 合計金額` の2数値のみ
  - 右ブロック: 1月〜12月の行に、要介護/要支援/委託の件数・金額と合計
- **レイアウトの版違いを確認**: 令和8年6月以降のシートは「月後れ請求」の前に「月後れ単価」列が1列追加されている。
  → 列位置固定ではなく **見出しラベルを起点** に読み取る。
- 検算関係（確認済）: `総売上 = 要介護合計 + 要支援合計 + 委託合計 (+ 認定調査合計)`。
  各小計行は `今月 + 月後れ = 合計`（件数・金額とも）。
- 試算表との関係（確認済）: 令和8年7月・8月の `総売上` は、試算表「居宅支援」部門の `居宅介護事業収益` と一致。
  **6月は管理表と試算表に差額がある**（照合画面に未照合差額として表示される）。
- **データ品質上の注意（実ファイルで確認）**:
  - あるシートでは対象年月セルが `令和○年○月`（未入力のテンプレート文字列）のまま金額が入っている。
  - `売上管理表 9月 `（令和8年9月分と思われる）の対象年月セル B3 が `令和8年8月` のまま（8月シートと年月が重複し、総売上が異なる）。
    → **8月・9月とも取込まれない。B3 を `令和8年9月` に修正すれば両月とも取込める。**
  - 右ブロック（年間表）の過去月の値が、後から作られたシートでは数円異なる（過去月の数値が書き換わっている）。
  → 取込時は **年月セルを唯一の根拠** とし、未入力・重複・検算不一致のシートは取込まずエラーログに記録する。
    シート名や他シートから年月を「推測」しない。過去の確定月の値が変わっている場合は上書きせず差分として保留する。
- 個人情報: 確認した範囲では利用者氏名等は含まれていない（件数・金額の集計のみ）。
- 対象外シート: `入力方法`（記入例。実在しうる数値が入っているため取込むと誤計上になる）・`リスト`（サービスコード一覧）は
  シート名で除外する（`KYOTAKU_NON_DATA_SHEETS`）。
- 利用者数: 居宅の利用者数は「今月請求件数（要介護＋要支援の今月件数）」で表示する（月後れ請求は前月以前の分のため除く）。

## 5. iBow 実施報告書（`Implementation (2).xlsx`）

- 形式: xlsx、1シート（シート名 `実施報告書`）。1〜3行目は空、**4行目が見出し**（83列）、5行目以降が1行＝**実施した訪問1件**。
- 確認したファイル: `(2)` は 2026年9月1日〜30日、`(1)` は 2026年10月1日〜16日（月の途中までのファイル。ダッシュボードには実績の期間を表示する）。
- 取込で使う列（これ以外の列は値を参照しない）:

| 見出し | 内容 | 取込 |
|---|---|---|
| `訪問日` | `YYYY-MM-DD` の文字列 | 訪問日 |
| `ID` | 利用者ID（4桁の文字列） | **HMAC でハッシュ化**（実利用者数の集計に使う） |
| `訪問種別` | `介護` / `医療` / `予防` / `サ(自)` の4値 | 訪問種別。これ以外の値はエラー |
| `開始時間` | `H:MM` | 保存しない（同日・同一利用者の複数訪問を区別する重複判定キーにだけ使う） |
| `提供時間` | 分（整数の文字列）。`終了時間−開始時間` と全行一致を確認 | 提供時間（分）。空欄は時間不明（0分にしない） |
| `主訪問者` | **職員の氏名** | **HMAC でハッシュ化**（職員数の集計に使う。氏名は保存しない） |

- 保存しない列の例: `年齢`・`要介護度`・`利用者の住所`・`同一建物 住所/施設名`・`副訪問者①〜③`（職員氏名）・`サービス内容`・各種加算フラグ。
- **職種の列は無い**（`複数名加算 職種` は複数名加算時のみ）→ 職種別稼働率は ZEST の値を使う。
- **キャンセル・中止の列は無い**（実施した訪問だけの報告書）→ キャンセル件数は ZEST の値を使う。
- 提供時間が空欄の行が3件（いずれも医療・開始時間も空欄）。件数には含め、時間は不明として扱い警告を出す。

## 6. ZEST 経営指標（`dashboard-経営指標.zip`）

- 提供されたファイルは **2026年10月分**（利用者より）。日数（平日21＋休日10＝31日）は10月（スポーツの日を休日に数えると平日21日）と整合する。

- 形式: zip（ファイル名 UTF-8）、`dashboard-経営指標/` 配下に UTF-8 の CSV が29個。いずれも**集計値**（個人単位のデータは無い）。
- ファイル名には記号の置換（`稼働率（_）_.csv`）や連番（`_1`・`_2`）が入るため、**1行目の見出しで CSV を識別**する。
- **どの CSV にも対象期間（年月）が含まれない**。→ アップロード時に対象年月の指定を必須にし、
  `平日・休日比較.csv` の日数合計（確認したファイルは 平日21＋休日10＝31日）が指定月の日数と一致しなければ取込まない。
  （9月（30日）を指定するとエラーになることを確認済。日数の合計だけを検算しており、同じ日数の別の月は区別できないため、月の指定は利用者の責任で行う）
- 訪問件数・訪問時間は `日別 x 職員の予定(サービスプラン・緊急)` ＝ **予定ベース**。iBow の実施実績とは別の指標として扱う。
- 取込む指標（見出し → 指標キー）:

| CSV の見出し（1列目） | 指標 |
|---|---|
| `日別 x 職員の予定(サービスプラン・緊急) 訪問件数_対象期間` | `VISITS_PLANNED` 訪問件数（予定） |
| `日別 x 職員の予定(サービスプラン・緊急) 訪問時間_対象期間` | `VISIT_HOURS_PLANNED` 訪問時間（時間） |
| `日別 x 訪問利用者(サービスプラン・緊急) 利用者数／初回訪問利用者数／停止利用者数／継続利用者数／ターミナルケア利用者数_対象期間` | `USERS` / `NEW_USERS` / `ENDED_USERS` / `CONTINUING_USERS` / `TERMINAL_USERS` |
| `キャンセル理由 キャンセル数_対象期間` | `CANCELLATIONS` |
| `職員 職員数_対象期間` | `STAFF_COUNT` |
| `年間カレンダー 常勤換算用結合Key`（2列目が値） | `FTE` 常勤換算 |
| `日別x職員想定受入可能件数 想定受入可能件数_対象期間` | `OPEN_SLOTS` 想定空き枠数 |
| `1件あたり移動時間（対象期間）` | `TRAVEL_MIN_PER_VISIT` |
| `先頭職種,稼働率` | `UTIL_JOB:<職種>`（`47.0%` → 0.47） |
| `チーム名,稼働率` | `UTIL_TEAM:<チーム>` |
| `キャンセル理由 キャンセル理由,キャンセル理由 キャンセル数` | `CANCEL_REASON:<理由>` |
| `サービス カテゴリー名,…担当者予定件数／担当者予定時間` | `VISITS_PLANNED_BY_INSURANCE:<種類>` / `HOURS_PLANNED_BY_INSURANCE:<種類>` |

- 2列目の `前期間比較`（%）、曜日別・サービス別・1日あたりの指標などは管理会計で使わないため取込まない（取込履歴に「対象外」と記録）。
- 職種名は ZEST の表記（`正看護師`・`理学療法士`・`作業療法士`・`管理者`・`事務`）のまま保存する。

## 7. iBow 月次売上（`SalesList.csv`）

- 形式: CSV、**Shift_JIS**、33列。
  - 1行目 `ステーション名：<事業所名>`、2行目 `提供月：YYYY年MM月度`（**対象年月はこの行から読む**）
  - 3行目が見出し、4行目以降が1行＝利用者1人、**最終行が合計行**（利用者ID空欄）
- 見出し（保険種類ごとに同じ構成）: `利用者ID` / `医療提供回数, 医療総金額, 医療給付割合, 医療自己負担額, 在宅がん医療総合診療料金額, 医療公費番号1, 医療公費番号2` /
  `介護提供回数, 介護総単位数, 介護総金額, 介護給付割合, 介護自己負担単位数, 介護自己負担額, 介護公費番号1, 介護公費番号2` /
  `予防…`（介護と同じ構成）/ `定期巡回…`（同）/ `サービス提供回数`
- 取込: 保険種類ごとの `総金額`・`提供回数`・`自己負担額` を全利用者で合計し、**合計行と一致することを検算**。
  総金額の合計を訪問看護の月次売上（推計値・`RevenueFact(source=IBOW_SALES)`）とする。
- 保存しない: `利用者ID`（利用者別の明細は保存しない）、**`公費番号`（公費の種類から疾病等が分かる医療情報）**、給付割合。
- 2026年9月分（実ファイル）: 医療・介護・予防の合計が合計行と一致。定期巡回は全行空欄。
- `在宅がん医療総合診療料金額` は全行0。値が入った場合に `医療総金額` に含まれるか未確認のため、売上に加えず警告を出す。
- `介護提供回数` は Implementation の介護の訪問件数と一致しない（数え方の単位が異なる）ため、両者は照合しない。
- 試算表との照合: `訪問看護事業収益` と比較する（試算表に9月度が計上された時点で確認できる）。

文字コード（UTF-8 / Shift_JIS）は取込時に自動判定する。
iBow は訪問看護のシステムのため、事業所列を割り当てない場合は訪問看護として取込む（列がある場合は値の対応表が必須）。
売上の照合先は、訪問看護＝試算表「訪問看護事業収益」、居宅＝「居宅介護事業収益」（居宅は実データで一致を確認済み、
訪問看護は SalesList.csv の提供後に確認が必要）。
