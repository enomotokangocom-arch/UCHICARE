# 12. CEO Morning Wireframe

## 12.1 デザイン方針

Apple / Linear / Notion / Stripe を参照点とした、Minimal・Premium・Data Driven・Fast・Executive orientedな
UI（19章）。情報量を絞り、「今、何を判断するべきか」を最も目立たせる。医療システムにありがちな
詰め込み型・古い配色のUIにはしない。

- 配色: ベースはオフホワイト/ダークニュートラル、Severity色のみアクセント（CRITICAL=赤、WARNING=琥珀、INFO=青）
- タイポグラフィ: 数値は大きく・太く、説明文は控えめなグレー
- 余白を惜しまない。1画面に詰め込みすぎない（TODAYは最大5件までという制約もこの思想の一部）

## 12.4 カード内の情報階層（優先度順）

1. Severity（色+ラベル） — 0.5秒で緊急度がわかる
2. 問題の一文サマリー（数値入り、太字）
3. 主な原因（箇条書き、最大3点）
4. 予測影響（金額、CALCULATEDバッジ）
5. AI推奨Action（番号付きリスト、AI ESTIMATEバッジ、Confidence%）
6. CTA（承認/修正/保留/詳細を見る）

## 12.5 データソース区分バッジ（22章準拠）

各数値・文言の横に小さなバッジを表示し、情報の性質を常に明示する。

| バッジ | 意味 | 表示色 |
|---|---|---|
| `FACT` | データに存在する事実（例: 終了者5名） | グレー |
| `CALCULATED` | コードによる決定論的計算（例: 予測影響額） | 青 |
| `AI ESTIMATE` | LLMによる推定・仮説・提案 | 紫、必ずConfidence%を併記 |

## 12.6 Confidenceが低い場合の表示

Confidence < 50% のカードは、CTAの「承認」ボタンを「判断保留を推奨」という補助テキスト付きの
セカンダリボタンにし、「保留」をデフォルトの推奨導線にする（22章の判断保留原則）。
