# 1. PRD（Product Requirements Document）

## 1.1 プロダクト概要

| 項目 | 内容 |
|---|---|
| プロダクト名 | Uchi OS |
| コンセプト | 医療福祉経営の意思決定をAI化する経営OS |
| 一言定義 | Dashboard ではなく **Decision OS** |
| 初期ターゲット市場 | 訪問看護ステーション（単独〜複数拠点、年商5,000万〜10億円） |
| 拡張市場 | 居宅介護支援・訪問介護・通所介護・障害福祉・高齢者施設・医療法人 |

## 1.2 課題

訪問看護経営における重要な意思決定（採用、拠点撤退・出店、稼働率管理、営業先の優先順位、
資金繰り、人件費適正化など）の多くが、経営者・管理者個人の経験と勘に依存しており、

- 異常の発見が遅れる（気づいた時には売上が数ヶ月悪化している）
- 原因分析に時間がかかる、または属人的で再現性がない
- 「何をすべきか」まで落とし込めず、判断が先送りされる
- 複数拠点になるほど、経営者の目が届かなくなる

という構造的な問題を抱えている。

## 1.3 プロダクトの基本思想

```
通常のBI:      データ → グラフ → 人間が考える
Uchi OS:       データ → 異常検知 → 原因分析 → 将来予測 → 意思決定 → Action生成 → 人間が承認 → 実行 → 結果検証
```

Uchi OS は「経営者が毎日行っている認知・分析・判断・指示の大部分をAIへ移管する」ことを目的とする。
ただし、**採用・解雇・給与・投資・出店・撤退等の重要判断は必ず人間の承認を経る**（12章・11章参照）。

## 1.4 ターゲットユーザー / ペルソナ

| ペルソナ | 役割 | 主な利用シーン | 利用頻度 |
|---|---|---|---|
| 理事長・経営者（Primary） | 複数拠点の経営全体の意思決定 | 朝の CEO Morning 確認、Action承認、AI経営参謀チャット | 毎日 |
| 拠点管理者 | 単一拠点の運営（稼働率・利用者・スタッフ管理） | Station Dashboard、Alert対応、Actionの実行 | 毎日〜週次 |
| 営業責任者 | 紹介元開拓・営業活動管理 | Sales Dashboard、営業系Decision対応 | 週次 |
| 人事・採用担当 | 採用・離職管理 | Workforce Dashboard、採用系Decision対応 | 週次 |
| バックオフィス/経理 | データ入力・請求・給与突合 | Data Import、Financial Dashboard | 月次 |

## 1.5 成功指標（North Star & Supporting Metrics）

| 指標 | 定義 | Phase1目標 |
|---|---|---|
| North Star | 経営者が CEO Morning を開いてから5分以内に「今日判断すべきこと」を理解できる | サンプル企業デモで達成 |
| Alert精度 | 生成されたAlertのうち経営者が「有用」と判定した割合 | 計測基盤のみ用意（目標値はPhase2以降） |
| Action実行率 | Human Approved になったActionのうち Completed に至った割合 | 計測基盤のみ用意 |
| Time to Insight | データ投入からCEO Morningが表示可能になるまでの時間 | 数分以内（Phase1） |

## 1.6 プロダクト原則

1. **重要な経営数値はコードで計算する。LLMには計算させない。**（17章・8章参照）
2. **FACT / CALCULATED / AI ESTIMATE を画面上で常に区別する。**（22章参照）
3. **人間の承認なしにAIが重要な経営判断を実行しない。**（11章参照）
4. **患者の氏名等の直接識別情報は、原則としてAIに送信しない。**（16章参照）
5. **データがない場合は数字を創作しない。Confidenceが低い場合は「判断保留」を選択できる。**
6. **段階的リリース。Phase1で全機能を作らない。**（25章・02-mvp-scope.md参照）

## 1.7 非対象（Out of Scope, MVP全体）

- レセプト・請求システムとの自動連携（Phase1-3では対象外。Adapter Layerで将来対応）
- 電子カルテ・記録システムとの統合
- Multi-Agent化（AI CFO/COO/CHRO/Sales Directorの個別Agent化）— 将来構想として設計はするが実装しない
- モバイルネイティブアプリ（レスポンシブWebで対応）

## 1.8 競合・代替手段との違い

| 代替手段 | 限界 |
|---|---|
| 汎用BIツール（Looker等） | グラフを出すだけ。原因分析・Action生成・承認フローがない |
| 汎用生成AIチャット（ChatGPT等） | 訪問看護特有のKPI・Decision Ruleの知識がなく、データ接続もない。数値を計算ではなく生成するため信頼性が低い |
| 紙・Excelでの経営会議資料 | リアルタイム性がなく、異常検知が属人的 |

Uchi OS は「決定論的な計算エンジン + ルールベースの異常検知 + LLMによる説明・示唆生成 + 承認ワークフロー」
を統合した点が差別化要素。
